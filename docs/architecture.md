# Architecture and assumptions

The board runs the user's MAIN at its original entry with four AArch64 CPU
contexts, a GIC and inferred memory windows. Device implementations admit only
the observed access widths, parameter fields and control sequences. Unknown
MMIO stops execution and records the CPU, PC, address and access in stderr.

## Boot and external peers

The complete camera boot ROM, persistent storage and external controllers are
not present. Explicit fixtures provide empty storage geometry, bus windows,
revision/strap values, ADC samples, orientation and selected status inputs.
The original firmware loads its own objects and runs its own scheduler/tasks.

The host MCU peer clocks the modeled SPI FIFO, receives original requests and
supplies synthetic replies. The GPIO edge model is incomplete: hardware
breakpoints coordinate explicit GIC inputs with the original ISR boundaries.
This is debug-assisted peripheral servicing, not a measured physical MCU.
Panel/sensor write peers return dummy RX only within the documented request
shape. They do not claim to recover sensor identities or programming tables.

Some sensor resource bodies are absent. An explicitly periodic external peer
supplies global and auxiliary boundary status independently of guest PC.
That is a functional substitute, not an inferred sensor command sequence.
Missing statistics currently include diagnostic zero inputs. Numeric exposure
display therefore must not be described as working physical AE.

The supplied profile uses single-thread instruction time with an optional
CPU3 WFE/SEV sleep model. External boundary inputs and key spacing use virtual
time, while host capture uses wall time. Two synthetic line-duration ROM
coefficients keep original timing arithmetic nonzero. The model, independent
tests and limits are described in [service-core events](service-events.md).

## Pixels and ownership

1. Load a local linear Bayer input. No scene image is stored in this repository.
2. Accept the firmware's source gates, processing parameters and output ring
   submissions through MMIO.
3. Perform a generic RGGB-cell conversion/resampling and produce the supported
   NV12/NV16 output planes in the submitted bounded guest RAM ranges.
4. Signal completion only after the synchronous pixel writes finish. Keep
   latched pending causes until the original ISR acknowledges them.
5. Let original tasks submit graphics and LCD sources. Render the supported
   paths, glyph/image operations, strokes, coverage and alpha in the emulator.
6. Scan out the original overlay over the guest video planes. The browser
   simply displays that surface.

Descriptor replacement requires a complete submitted bank. Until a fresh
bank is complete, the model reuses the last complete bank. This is an explicit
functional ownership/pacing assumption. Counters distinguish frames, bytes,
descriptor batches, reuse, pending causes and acknowledgements.

Source drain interrupts use the original driver/ISR bit mappings. DMA is
synchronous in this model, so stopping has no queued asynchronous write to
wait for. This does not reproduce silicon drain latency. W1C, mask retention,
independent causes and restart are modeled separately from frame completion.

## Graphics

Raw clear commands support one-, two- and four-byte elements, retaining row
padding and rejecting unmapped or unaligned destinations. The functional
model repeats the low element bytes of the packed color. The two-byte path
is used by native menu-return plane clears; physical GPU fill semantics have
not been measured. Three-byte elements and nonzero write masks remain unknown.

The renderer implements selected observed packet families and blend modes.
It accepts original program submissions; two supported program prefixes are
identified by SHA-256, with no embedded instruction bytes. Color coordinates
and table selectors are generated by formulas. Tone/color coefficients and
fonts/icons are read from the user's running guest, not shipped as assets.

Coverage uses a regular sample grid for the observed quality mode. It improves
edge appearance but is not a measured GPU sample pattern. Alpha is separate
from color; a zero-alpha black pixel and an opaque black outline have different
meanings. RGB/BGR ordering is explicitly handled at each boundary.

## Capture, storage and recovery

The separate [capture profile](capture.md) opts into full-frame Bayer transport,
packed-14 RAW output, neutral NR, cropped NV16 conversion, owned stream and
thumbnail buffers, and libjpeg encoding. The firmware chooses objects,
controls submission, receives actual completion and writes the NEF metadata
and streams. This model is not a Nikon compression or physical ISP implementation.

A DesignWare adapter maps the observed DBI/ATU interface and bounded work/image
RAM apertures to upstream QEMU PCIe/NVMe. A new sparse exFAT image is the only
storage destination. Native writes and initialized file contents are checked
separately; a filesystem entry alone cannot prove a valid photograph.

The MCU peer acknowledges only the observed, complete CCOMP request; the
request/feedback GPIO device retains normal mask/pending/W1C ownership.
Source stop resets invalidate old ownership while allowing a complete new
submission. The secondary source follows its own gate/mode during restart.
Capture recovery waits for real RAW and all three JPEG completions, fresh
RAW/LCD frames, actual PHOTO-menu surfaces and fresh frames on each return.
This avoids accepting exposure-time menus or old visible frames as recovery.
