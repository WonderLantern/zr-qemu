## 本轮改动

| 选项（默认关闭，实例化后不可修改） | 行为与边界 |
| --- | --- |
| `video-primary-boundaries-model` | 真实内部 RAW 输入及六路 Y/UV 写入完成后发布主图像输入/输出原因；原 IRQ mask 与分别 W1C 确认控制交付和缓冲区复用，reset 取消所有权。合并阶段和物理时序未证明。 |
| `engine151-active-program-model` | 已通过完整 START 的 ISP 配置与参数有效位图一起锁存，下一配置准备不能误停当前活动流。下一 START 仍严格检查新参数，STOP/hold/reset、真实输入及输出约束继续生效。原机 ISP 算法和物理寄存器生效阶段未证明。 |

只读状态区分活动流就绪与下一次 START 就绪，并列出真实传感器门控。
写入命令寄存器读回为零，不等于实际门控关闭。ZR 的 main10/r3d 配方
切换到本轮组合；旧 C0/source0 END 失败实验保持关闭，照片/取景默认不变。
ZR 默认横屏、明确记录的英文缓存偏好；VIDEO 按原厂半按加全按启动，
随后全按停止，半按对焦。ZR 原固件地址不可直接当作 Z9 的绑定。

## 证据与未完成项

同一私有构建通过两机型 22 个已停止 QTest guest、214 项检查：活动配置
10/108，主图像边界 12/106。覆盖实际输入代际、六路输出与 padding、

这些诊断没有执行原固件指令，不代表相机录像通过。

历史 537/538 两种原固件整轮均已结束：Main10 第二 START/state98 超时，R3D
STOP/state82 超时。编码器图像输入和编码图片均为零。R3D 已越过旧的
三输入停点，首次 REC 内原准备任务与帧桥各执行九次；帧桥启用字段仍为
零，未进入编码队列。必须继续满足两次启停、实际卡文件、整段独立解码、
新取景帧和菜单恢复。历史 NEF/拍摄证据保留原构建范围，公开新二进制
未重新通过完整原固件照片/录像验收。

无效 START 会请求 QEMU debug 暂停。负例 QTest 必须先明确验证暂停，再
恢复无原固件执行的诊断时钟测试后续合法请求；原固件故障不自动恢复。
观察器只读，不修改固件 PC、任务标志、OS 返回或成功回调；模31源等待
与图像准备使用不同事件对象，不能只凭相同位值认定同一硬件原因。
当前公开构建和无固件检查记录在 `source-snapshot.json`。

原 Nikon ISP/DSP/H265/RAW 压缩/JPEG 均未验收；现有 Bayer、FAST9/SAD、
x265/x264、开源 F0、WLVR/zlib、libjpeg 是明示的功能替代。WLVR 不是
REDCODE/R3D。XM6 资料已有但版本对应未确认；NeuPro 详细资料缺失，
本地神经网络复现 inconclusive。合格录制发布仍要求两种格式均通过。

本次仅发布用户要求的源码开发快照：不上传固件、解密私有代码、微码、
ROM/校准资源、字体图标、厂商 SDK、用户素材、截图、影片、卡镜像、
原始追踪或私有 Git 历史。源码清单与全部可达历史/blob 审查用于防止
意外上传，不能自动判定版权。详见 [英文完整说明](shared146.md)。
