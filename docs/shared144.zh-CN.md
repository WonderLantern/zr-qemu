# shared144 开发快照

本次将 Z9、ZR 两仓库从 shared138 同步到 shared144，包括共享板级设备、
Bayer 输入、像素处理、ZR 原厂视频操作配方和只读观察工具。
Z7 保持原样；用户自行提供固件，ZR 还需要独立校验的本地捕获资源，
仅有 MAIN 固件不能运行当前完整配方。构建与启动命令见仓库 README。

## 本次新增

- 第二 ISP 功能路径：核对几何、源模式、输入所有权与输出缓冲区，
  使用明确标注的功能算法产生六个 Y/UV 输出平面。
- 第二传感器输入：旧接收器和解码器退役后，根据用户 RAW 生成新的
  CFA 重采样输入；有独立输入代际和待消费状态，不复用旧解码帧。
- 第二图像源 END：三次实际输入及输出完成后产生独立待确认事件，
  等待原驱动确认后才允许复用；物理分组与时序没有得到证明。
- 接收器启动顺序：完整配置的接收器可以先于供应端 enable 启动，
  实际像素处理仍等待真实输入和原供应端开启。
- 只读观察器支持明确的记录上限及单独计数的过滤事件；当前配方
  同时观察普通帧桥和另一条 RAW 帧桥，未修改固件指令或任务结果。

新增设备选项默认关闭。ZR 的 `--profile main10`、`--profile r3d`
启用当前实验组合；之前失败的 C0 完成和 source0 END 实验保持关闭。
预览与照片默认配方没有开启这些新视频选项。ZR 默认为横屏和明确记录的
英文缓存偏好；视频模式半按对焦，保持半按后全按开始，再次全按请求停止。
ZR 的地址和固件绑定不能直接复制到 Z9。

## 验证与未完成项

私有 shared144 的接收器顺序与实际数据路径检查为两机型 10 个诊断 guest、
34 项检查。此前 shared143 的 114 项结束事件检查、shared142 的 66 项
新传感器检查保留各自构建范围，不累加成当前整机验收。两份公开包重新
构建并执行无固件测试，具体指纹与结果记录在 `source-snapshot.json`。

最新原始 ZR 固件整轮测试中，Main10 已通过首次 START 通知和 STOP，
但在第二次 START 超时；R3D 等待 STOP 超时。两个自有进程均已退出，
编码器图像输入与编码图片均为零，尚无合格影片。
必须完成两次 START/STOP、实际写卡、整段独立解码、取景与菜单恢复，
才算录像通过。H.265 10-bit 与 R3D 都通过后才发布合格录制版。

此前全部 20,811,648 个模型传感器输入样本与独立重采样结果一致，
这个结论只证明模型输入内容，不证明物理 CMOS 格式、图像已到编码器，
也不证明原厂 ISP。旧照片/NEF 的验收仍属于当时记录的构建，
当前公开新二进制没有完成新的原固件照片或录像整轮复验。

## 重要更正及复用边界

此前称为“帧组提交”的函数实际更新源 DMA 缓冲区表和 bank，
调用或返回不等于处理完帧，更不等于电影队列收到了图像。
需要分别核对登记目标、实际 DMA、帧队列和编码器图片提交。
另一条 RAW 帧桥的名称也不能作为 REDCODE/R3D 编码成功的证明。

原厂 ISP、DSP、H.265、RAW 压缩、JPEG 算法均未验收。
现有 Bayer、FAST9/SAD、x265/x264、开源 F0、WLVR/zlib、libjpeg
属于功能替代实现；WLVR 不是 REDCODE 或 R3D。
XM6 本地资料存在但 SDK/固件版本对应未确认；NeuPro 详细编程与算术
资料缺失，本地神经网络复现 **inconclusive**。

共享设备、所有权契约、构建和观察工具可以复用；固件地址、IRQ 客户端、
图像布局与资源必须逐机型、逐固件验证。完整英文变更与属性表见
[shared144](shared144.md)。仓库不包含尼康固件、解密私有代码、微码、
ROM/校准/字体/图标、厂商 SDK、素材、录像、卡镜像、原始追踪或私有 Git 历史。
